# core:siagie

Reads and fills the Excel templates SIAGIE generates. JVM-only, no Android and
no dependencies beyond the platform: `java.util.zip` for the OPC package and the
DOM parser for the one sheet part being edited.

`docs/adr/0005-siagie-workbook-io-uses-targeted-opc-edits.md` records why there
is no spreadsheet library here.

```kotlin
val template = XlsxTemplate(File(directory, "6 Primaria EBR.xlsx"))
template.sheetNames()
template.readSheet("PPSS")
template.fill(target, mapOf("PPSS" to mapOf("D4" to "AD", "E4" to "Conclusion")))
```

Reading the roster of a grades template goes through the domain port
`SiagieRosterReader`:

```kotlin
val reader = XlsxSiagieRosterReader()
reader.read("6 Primaria EBR.xlsx", bytes)
```

It returns the Students of the first sheet (every sheet carries the same roster),
the Grade written in the title row or in the file name, and the Section name when
the file carries one. A file that is not a grades template comes back as
`SiagieRosterResult.NotASiagieTemplate`.

`fill` copies every part it does not edit byte for byte, so styles, dropdowns,
frozen panes, hidden ids and sheet order survive. The target file name is the
caller's choice and must stay the one SIAGIE generated.

## Fixture

`src/test/resources/6 Primaria EBR.xlsx` is shaped like the primary grades
template described in `docs/siagie/README.md`: one sheet per Area, header rows
1-3, data from row 4, the NL dropdown, per-cell styles, frozen panes and the
legend block. Text is stored in `xl/sharedStrings.xml`, as a real SIAGIE file
does. It is modelled from the Minedu instructives, not generated by SIAGIE.

Regenerate it with:

```sh
python3 -m venv .venv && .venv/bin/pip install openpyxl
.venv/bin/python tools/generate_fixture.py "src/test/resources/6 Primaria EBR.xlsx"
```
